Parallelism strategies

How each strategy maps onto the GPU / node / fabric stack

Data parallelism

Every GPU holds a full copy of the model. The batch is split across GPUs; each computes forward and backward independently, then gradients sync once per step.

Tensor parallelism

A single layer's weight matrix is split across GPUs. Both get the same input, compute their partial output, then combine before the next layer — synchronous, every layer, needs NVLink.

Pipeline parallelism

The model is split by depth, not width. Each GPU owns a contiguous block of layers; activations flow forward stage to stage, like an assembly line.

Expert parallelism (MoE)

A router looks at each token and sends it to just one or a few "expert" sub-networks, each living on a different GPU. Traffic is bursty and uneven per expert.

Sequence parallelism

A single long input sequence is split across GPUs rather than the model — needed when one sequence's activations don't fit in memory on one GPU. Usually paired with tensor parallelism in the same NVLink domain, since attention needs tokens to talk across the split.
